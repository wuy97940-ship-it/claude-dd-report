> ⚡v5.9两条最高铁律：①**勾稽不平 = 强制回溯原始凭证**（哪怕扫描件）定位到具体栏位，禁"记录差异"了事；②**实控人/董监高/股东必须与工商登记交叉核对**，禁照抄业务报告；专有名词进正文前必验真。

## 最终目标

不是"写得像一份尽调报告"，而是真正完成：**调查员+财务分析师+风险经理+授信审批辅助+报告编辑+Word排版员+最终审稿人**。产物必须达到：信息密度高、证据链完整、风险识别深入、授信逻辑清晰、数据口径统一、版式稳定、**可直接送项目会/授信评审**。

# 一、铁律与最高优先级原则

## 工程铁律（源自历次返工事故）
1. **永远不从零生成docx**（python-docx新建=格式必跑偏，v1/v2生成器已废弃）
2. **永远拿同业务线最新定稿报告当格式母版**——字体/缩进/行距/表格样式全克隆，不靠猜
3. **数据层与逻辑层分离**——内容写content.json，构建器零硬编码（重建场景）
4. **有FAIL禁止交付**——QC门禁全过才算完
5. **授信要素以业务最新口径为准**——额度/账期/增信随时变，变更只改content.json重建
6. **改docx只走python-docx通道**——禁zip解包+ElementTree整体重写（曾致文件损坏）
7. **每次手术前必备份当版本**，每步后Word COM立即验证（不攒到最后）

## 终审人最高优先级原则（必须同时满足）
1. **事实准确**：关键数据/日期/主体/金额/比例/结论均有来源，或明确标注访谈/测算/估算
2. **尽调有深度**：不止描述，持续回答"发生了什么、为什么、意味着什么、对授信有什么影响"
3. **模板不跑版**：用户给定模板=硬约束，不擅自改造章节/表格结构/版式/视觉层级
4. **可审查**：任何重要判断都能回溯到事实、数据和分析逻辑

## 禁止清单
- 禁止编造缺失数据；禁止为让数字"看起来合理"而自行修正源数据
- 禁止把推测写成事实；禁止空泛套话代替分析
- 禁止无依据给出"风险可控/竞争力强/偿债能力较好"等结论
- 禁止模板已有表格时随意重建；禁止凑字数重复同一观点
- 禁止空口声称完成，必须附执行证据

# 三、标准流水线（先调查→再写作→再排版→再审稿）

禁用"一次生成整篇"的单步模式。12步流水线：

**资料接收 → 主体识别 → 证据台账 → 数据清洗 → 财务核验 → 风险扫描 → 授信分析 → 章节写作 → 模板填充 → Word排版 → 自动质检 → 最终审稿**

工具映射：
```
资料接收/主体识别  → dd_extract_docx.py / dd_extract_xlsx.py（逐份精读+提取清单给终审人）
证据台账/财务核验  → 企查查MCP + 所配财务数据接口 + 征信/审计报告交叉验证
章节写作/模板填充  → content.json + dd_report_builder.py（格式母版法）
自动质检           → dd_report_qc.py + 本文「质检清单」
Word排版/最终审稿  → Word COM更新目录 + 终检 + 模拟审稿
```

## 输入优先级（用户同时给模板+历史样本时）
1. **当前项目正式模板**：决定版式/标题层级/页眉页脚/表格结构
2. **历史优秀报告样本**：决定内容颗粒度/分析深度/措辞风格/风险表达
3. **其他资料**：只提供事实数据背景，不改变前两者的写作规范

## 建立模板地图（读模板后必须记录）
页面尺寸/页边距/页眉页脚/页码位置/封面结构/目录层级/一二三级标题样式/正文字体字号行距段距/表格数量及行列逻辑/表头样式/边框/单位写法/图表占位/风险提示模块/备注来源格式/分页规则。

# 五、数据口径纪律

## 口径锁定（涉财务必做）
明确：合并还是单体/年度还是季度半年度/期末余额还是平均/营业收入还是营业总收入/净利润还是归母净利润/含税还是不含税/集团口径还是单一主体/会计口径还是运营口径。
示例：> 本节所引数据均为上市公司合并报表口径。

## 禁止隐性换口径
前文用"归母净利润"，后文突然用"净利润"作净利率分子，必须显式注明。

## 数字计算规则
源数据A、B可算出C时：优先用计算值、内部核算、正文保留必要精度、四舍五入误差不强行追求完全一致。**派生数据全链重算**：关键假设（价格）变动时全链重算，保证逻辑自洽。

## 基本财务描述固定模板（终审人新规）
每个授信主体"公司基本情况/财务概况"段必须套用固定句式，最新期、上期、两期变化三项缺一不可：
> 截至<最新期末>：总资产X亿元、总负债X亿元、资产负债率X%；<最新年度>实现营业收入X亿元、净利润X亿元、净利率X%。上期（<上期末>）：…。两期比较：总资产±X%，资产负债率由X%升至/降至X%；营业收入±X%，净利润±X%（由X亿元增至/降至X亿元）、净利率由X%升至/降至X%。

- 总负债取报表"负债合计"行（勿用"资产-权益"自行相减）
- 净利率=净利润÷营业收入，脚本计算勿手算
- 变化表述化：盈利用"增长/下降X%"，比率用"由X%升至/降至X%"；扭亏/转亏用文字标注
- 上期未披露如实写"上期数据未披露"，禁止用增长率倒推伪装成披露值
- 多主体逐个套用；意见区用浓缩版

# 六、核心写作公式

所有重点分析遵循：
**事实 → 变化 → 原因 → 同业/历史对比 → 风险含义 → 授信影响 → 需要关注的变量**

❌ 不要只写："应收账款有所增加，需关注回款风险。"
✅ 应写成："2026年6月末应收账款43.15亿元，较2025年末增长87.61%，增速显著高于同期营收增速；主要受销量增长及下游账期占用影响。结合前五大客户集中度较高，表明收入扩张伴随明显营运资金占用，若下游回款放缓，将进一步压缩现金安全边际，对短期偿债和供应链融资形成压力。"

核心不是写长，而是把逻辑链写完整。

# 七、各章节最低分析要求

## 项目概况
谁申请/谁是授信主体/原额度/本次额度/增量/账期/用途/增信/为什么申请/额度如何测算/历史合作是否正常/当前交易规模与额度是否匹配。
**额度测算链条**：业务量→单价→月度采购→外采比例→授信周转次数→理论覆盖规模→占客户需求比例。

## 行业概况
至少覆盖：行业定义及产业链/需求驱动/上游原材料价格/供需关系/竞争格局/主要玩家/产能产量出货量利用率产销率/行业周期/潜在新增产能/中长期风险/行业门槛/行业变化如何影响授信主体。
**⚡行业趋势图表标配（20260910终审人指令）**：行业章节应配"近五年目标市场供需/装机/出货量柱形图"（趋势可视化）。获取通道（按优先级）：①新浪财经研报摘要页含券商研报原图直链（n.sinaimg.cn/...png），批量下载后PIL裁剪；②InfoLink等机构官网文章配图；③机构报告正文数据自绘。插入规范：图片居中宽约13.5cm，图注用备注五号字样式，注明口径（装机vs出货/欧洲vs欧盟）+原始来源+转引出处；正文需有与图衔接的叙述；数字只能写来源披露值，禁目测图值。行业章节插入图后Word COM渲染验收。
**必须落回客户**：该行业变化对本项目客户的盈利、现金流、存货、应收、融资能力及回款有什么影响？

## 行业门槛
至少从：技术与工艺/客户认证/资金/产能建设/供应链稳定性/成本控制/产品迭代。

## 公司基本情况
成立时间/注册资本/实缴资本（必带币种"X万元人民币"）/法定代表人/实控人/股权结构/历史沿革/关联企业/主营业务/生产基地/产能/产销量/主要客户/主要供应商/上下游结算与账期。

## 实际控制人
不止简历。还分析：持股比例/是否质押/是否冻结/是否失信/控股企业/控制稳定性/关联主体风险。

## 财务分析
- **资产负债表**：货币资金/受限资金/应收账款/应收票据融资/预付款项/存货/固定资产/在建工程/短期借款/应付票据/应付账款/一年内到期负债/长期借款/总负债/净资产/资产负债率
- **利润表**：收入/成本/毛利额/毛利率/期间费用/营业利润/净利润/归母净利润/扣非/非经常性损益减值
- **现金流量表**：销售收现/经营/投资/筹资现金流/现金净增减/期末现金及等价物
- **必须识别**：盈利是否真实/现金流是否匹配利润/收入增长靠价格还是销量/应收存货是否过快增长/负债增长是否快于资产收入/外部融资依赖/短期偿债缺口/资产受限/经营拐点是否可持续

## 财务三表标准列（终审人固定审阅习惯，默认执行）
- 资产负债表：项目|最新期末|占比|上期末|较上期末变动|再上期（占比口径：资产÷总资产、负债÷总负债、权益÷所有者权益）
- 利润表/现金流量表：项目|本期|上年度|变动比例|再上期（变动比例=本期÷(上年度/12×本期月数)-1，同期折算）
- 比率变动用pct；时点数（期末现金）标"不适用"；亏损收窄/扭亏/由负转正用文字标注；三表下加五号字备注说明折算口径

## 财务深度规则（每个重要科目必答五问）
1.规模有多大？2.变化有多快？3.为什么变化？4.和收入/利润/现金流是否匹配？5.变化会怎样影响授信？

**重点科目专项**：
- **应收账款**：绝对额/占总资产/占营收/增速vs收入增速/周转天数/前五大集中度/第一大占比/账龄/坏账准备/大客户信用/回款周期/对现金流影响
- **存货**：绝对额/增速/占流动资产/周转/原材料在产品库存结构/是否涨价备货/跌价风险/价格敏感度
- **货币资金**：区分可动用/受限/保证金/信用证保证金/票据保证金
- **借款**：区分短期/一年内到期/长期/有息/银行融资/票据融资/是否集中到期
- **经营现金流**：必答"为什么经营现金流与利润不一致？"禁止只写"经营现金流为负，风险较高"

# 八、同业比较 / 压力测试 / 信用担保

## 同业比较（可比性优先⚡）
**可比公司必须业务模式/工艺可比**——客户丁0902教训：终审人否决三个电池回收标的（工艺不可比，"都不是一个工艺"）。正确做法：
1. 优先找**同工艺赛道**企业；若赛道无上市公司（如电解铝废渣提锂），用**同工艺非上市企业对比**（产能/工艺/品位/投产时点）+**工艺原理相近上市公司参照**（明示差异）
2. 不能为有表格而做表格，至少形成一个判断维度：市占率/技术路线/产能规模/毛利率/净利率/资产负债率/应收周转/存货周转/客户集中度/经营现金流/有息负债
3. 至少回答：客户比龙头强在哪/弱在哪？当前风险是个体还是行业共性？哪些风险可用授信条件控制？
4. 避免：只罗列排名/只列财务数据/没有结论/不同口径数据直接比较
5. **表格之后必须有结论**（至少1段：最重要的变化是什么？为什么？对客户意味什么？）

## 负债到期与现金流压力测试
授信额度大、短债压力明显时原则必做。至少含：期初可动用资金/经营/投资/筹资现金流/现金净增减/期末可动用现金。
**至少三情景**：悲观/基准/乐观。**压力变量**：原材料价格/产品价格/销量/毛利率/应收回款周期/存货占用/银行借款续作率/资本开支。
**最终必答**：什么情况下出现现金缺口？缺口多大？依靠什么解决？
**客户丁0902现金流新规则**：尽调测算的是**授信主体自身的现金流**（盈亏平衡出货量、毛利/现金流转正、资金缺口、母公司/实控人拆借需求），不是我司业务收益（业务收益业务报告自己算）。前提假设必须明示、参数可调、结论做敏感性。

## 信用/司法/担保/抵质押（形成专项核查结论）
检查：失信被执行/被执行/经营异常/行政处罚/重大诉讼/买卖合同纠纷/对外担保余额/担保对象/集团内互保/动产抵押/不动产抵押/股权质押/货币资金受限/固定资产抵押/无形资产抵押/实控人股权质押。
**担保必做"余额/净资产"分析**：如"担保余额69.48亿元，占最近一期经审计净资产139.21%，虽均为集团内担保，仍应关注集团层面或有负债与融资依赖"。

# 九、意见区与写作规范

## 意见区七条（落点=风控决断⚡）
1. 摘要层不重复正文；2. 小标题语义化编号化；3. 口径"最高不超过X"；4. 口径变更全篇同步（Grep）；5. 风险提示可延伸至参股/关联布局风险；6. **★最高原则=意见结尾落一句可执行风控决断，而非①-⑤措施清单**（识别弱信主体→"不应共用额度，应当限额"）；7. 风险做减法、结论层剥脂、措辞克制、标题简化、**意见独立一页**。

## 核心前言结构（项目会版）
**【项目需求】**一段，交代额度/主体/账期/用途/增信。
**【基本面】**3-5条，高信息密度，覆盖公司地位/经营/客户结构/历史交易。
**【重点风险提示】**3-5条，按重要性排序。
**【总体评估】**2-3条，形成授信意见。

## 风险提示写作规范（具体/量化/可跟踪）
每项重点风险采用：**风险名称+数据证据+原因+可能后果+监测指标**。
❌"公司存在一定经营风险。"
✅"2026年半年度经营现金流净额-12.36亿元，上年同期-7.63亿元，缺口扩大；同期应收账款43.15亿元较年初+87.61%、存货27.06亿元+117.03%，若下游回款滞后或碳酸锂价格回落，营运资金占用和融资需求可能进一步上升。"

## 总体评估规则（不能重复风险提示，做平衡判断）
正面因素：客户地位/行业地位/客户资质/盈利改善/交易历史/回款记录/增信。
负面因素：现金流/短债压力/客户集中度/行业产能/资产受限/有息负债。
**最终授信判断必明确**：同意/不同意+授信额度+账期+主体+用途+是否需增信+风控条件+后续跟踪指标。禁止含糊表达。

## 表格规则
- 必须用表格的场景：多公司对比/多期财务/客户供应商明细/授信变化/产能对比/借款结构/压力测试/股权结构/资产受限
- 表格必有单位（如"单位：亿元"），金额比例数量统一
- 表格不塞长段落，解释性内容放表前后
- 重点表格之后必须有结论
- **表号-实体表一致性（客户丁0904）**：交付前逐一核对每处"表N："标题，确认其后紧邻确有对应表格/图片；无实体跟随的空标题=悬挂引用（只因前轮手术删表遗留），须补表或删标题。
- **一表一含义**：一个表格对象只承载单块同构数据，表头列数=语义列数、无重复列（"省份||省份"这种重复列是表头错位）；导语/表标题/解释文案放表格外独立段落，绝不塞进单元格（防"表3+表4+两段导语挤一个12×9表"这类错位）。

## "反AI味"规则
禁止批量使用低价值表述：总体来看/综合来看/值得关注的是/具有一定优势/面临一定压力/经营情况良好/发展前景较好/市场竞争力较强/风险总体可控。
这些词非绝对禁止，但后面必须紧跟事实依据。
句式倾向：> "数据显示……；主要系……；结合……，判断……；对本项目的影响主要体现为……"
而非：> "公司发展前景广阔，综合实力较强，未来具有较大发展空间。"

## 输出风格
银行/大型产业集团风控部门；客观克制专业；事实先于观点、数据先于形容词；风险表达具体；不夸张风险、不美化客户；结论与证据严格对应。

# 十、格式母版法与docx手术（工程执行）

## 标准5步流程（目标60分钟）
1. **确认三要素**：目标公司+素材路径 / 格式母版（同业务线最新定稿）/ 授信要素（额度账期增信，与业务确认，不从历史文档推断）
2. **素材提取与交叉核对**（不可跳过）：
```bash
python tools\dd_extract_docx.py <docx> <dump.txt>
python tools\dd_extract_xlsx.py <xlsx> <dump.txt>
```
逐份精读→提取清单给终审人→交叉核对（底稿与草稿不一致以原始凭证为准）→OCR/估算数据标"仅供参考"。
3. **编写content.json+qc_config.json**：章节骨架6章（意见/释义/项目概况/行业概况/公司基本情况/财务状况/同业可比/信用处罚/总结，可精简）；风险表覆盖7类（市场/经营/技术/资金/回款/物流/合规）。
4. **构建+QC门禁**：
```bash
python tools\dd_report_builder.py content.json <格式母版.docx> <输出.docx>
python tools\dd_report_qc.py <输出.docx> qc_config.json
```
exit 0=PASS；1=WARN评估；2=FAIL必修。
5. **Word COM更新目录页码+QC复验**。

## 格式母版选择铁律
- 生成docx的格式母版=同业务线最新定稿报告，**禁止拿本报告旧备份当母版**（旧备份样式可能未定义/缺"标题1"，全线带偏字号）
- **报警信号**：构建日志出现 `synthesized: h1` / `synthesized: unit` = 母版缺样式样本，立即换正规母版重跑
- 交付前终检：Word COM打开抽查正文段字号=母版Normal、章节标题=标题1、（一）小节加粗，与母版逐项一致

## 表格格式铁律
数字靠右/文字靠左/符号日期序号居中、表格水平居中、标题居中加粗、顶medium底thick两条大黑粗线（构建器自动执行）。数字右对齐注意 `+X%`/`-X%` 前缀与纯整数。

## docx手术安全铁律（修订/批注场景）
- **⚡动手前先读 `docx_edit_lib.py`**（v1.1 已有全套原语：`replace_in_para`**跨run**、`set_para_text_guarded`、`clone_row_after`/`delete_row`、`set_table_autofit`、`fix_ppr_order`）——客户庚0911未用该库、手写逐run替换，遇"数字被拆成独立run"时0处生效，白花一轮
- **⚡修订模式手术三铁律（v5.9，终审人立为铁律）**：①**新增/修改必须与全表全文格式一致**——写格函数**先取原型run再清内容**（顺序反了=新run无`rPr`=字号退回默认，本案被抓）；空单元格借兄弟单元格原型；**交付前逐格比对邻行的sz/字体/边框/对齐**；②**按文本内容定位，禁按段落/单元格序号**（Word重排/插段后序号即失效，本案踩过）；③**表内插多行从下往上插**（否则第二次克隆到刚插入的行、内容叠加）。配套坑：`tracked_replace` 会把批注区间挤成空区间（收尾需把`commentRangeStart`前移到修订块之前复位）；插多行后**列宽需按比例重分配**（tblW=pct时Word按gridCol比例缩放）
- **⚡修订叠加层写法**：底稿含上一轮未接受 `w:ins` 时——改**自己的插入**直接改 `w:t`（`ins_replace`/`set_ins_para`，等同改草稿不叠加标记）；改**用户原文/手改处**才用 `tracked_replace`。混用会让修订面板噪声爆炸
- **⚡Word自动化：PDF导出极慢不等于文件坏**：`ExportAsFixedFormat` 对含修订文档可能空转5分钟+；判据改为 `Documents.Open` 无修复提示 + 页数/修订数/批注数/表数正确。脚本必须**写文件日志 + `python -u`**（stdout缓冲会让人误判卡死）；确需渲染用**页范围导出**。Word自动化一律走 `dd_word_finalize.py`，禁手写ps1
- **⚡PowerShell 环境**：复杂 Python 一律**写 .py 文件再跑**，禁 `python -c "..."` 内联（引号/正则转义/中文路径反复踩坑）
- **只走python-docx/lxml原位手术**；禁zip解包+ET整体重写（除**批注部件清理**这一必要场景，须逐部件核对后写回并立即Word验证）
- **每次手术前必备份当版本**（含终审人手改）；禁止链条式覆盖无备份
- **⚡Word自动化顺序（不可颠倒）**：打开 → **`TrackRevisions=False`（必须在任何改动之前）** → `AcceptAll` → 刷新目录/域 → 保存。用 `dd_word_finalize.py` 一键完成，**禁手写ps1**（无BOM→中文路径乱码→Word报"文档已损坏"）
- **每步修改后立即Word COM验证**（能打开+页数+批注数+关键内容）
- **批注处理闭环**：`dd_comment_closure.py --dump`（文本+**精确锚定位置**，表格内会特别标注）→逐条分类【可立即解决/需业务提供/内容待定】→修订正文→`--close`清批注→Word验证
- **⚡批注锚点可能落在表格单元格**：删该行=连带删锚点，Word批注数莫名减少。删行前 `--row-guard T R` 查；清理必须**五部件（comments/commentsExtended/commentsIds/commentsExtensible/people）+ 三类锚点元素 + 5条Relationship**一起清，漏一个 Word 报损坏
- **注意Word保存可能重编批注id**，删除前按"批注文本+锚定段"二次定位，勿硬编码id
- **tracked-change手术用lxml直改**（_tc_helper：make_run/wrap_ins/wrap_del/tracked_delete_paragraph/tracked_delete_table/make_paragraph_before/insert_paragraph_after），author="Claude"
- **split_paragraph移动全部内容子元素**（r/ins/del/hyperlink/commentRange），否则修订元素遗留串位

- **TOC×修订交互**：新增标题若整段处于w:ins，`TablesOfContents.Update()`不显示；接受修订后刷新目录自动出现（告知终审人）

- **确证问题vs打磨**：数字矛盾/事实错误/缺失表=确证问题→改；措辞/格式重构=打磨→先确认。对含终审人手改的定型报告，拆表/重排/跨板块属跨板块变更，**先确认再动**；交付前对齐式diff证"预期改动外零内容删除"（防误删用户手改正确内容）。

# 十一、批注驱动修订闭环（终审人批注场景）

> ⚡**v6.0：本章的完整操作版见 `docs\frameworks\dd_report_revision_playbook.md`**（七步流水线 / 终审人偏好清单 / 12条踩坑自检 / 脚本骨架）。拿到带批注 docx 动手前先读它。

**⚡前置检查单（动手前30分钟，v5.5新增——四轮返工的最大教训是"改完→被打回→再学"）**：
1. **定版本**：扫项目目录找最新版本线（v_n+备份链），与终审人确认底稿——防止在过时版本上做重复劳动
2. **读批注**：提取全部批注（id/作者/锚定段/完整文本——锚定文本可能被截断须读comments.xml原文），逐条分类：改报告/进访谈问卷/需问终审人；识别终审人手改段落清单（diff上一版），**绝对不碰**
3. **提格式**：跑`tools\dd_format_probe.py <docx>`提取格式规范卡（正文/备注/单位/二级标题/编号标题六类母版参数+裸格式+hint+autofit三项体检）——新增内容逐类克隆，不裸写
4. **摸结构**：章节顺序/表格索引/交叉引用（"详见X（X）"全清单）、目录与正文一致性
5. **口径三问**写进修改方案：①主体口径（哪个主体的合并？）②期间口径（与报表一致？账期可沿用标注）③分母口径（占比与报表总额勾稽？）——不确定的列出来问终审人，不猜

**Word批注=需求文档、content.json=唯一事实源、docx=渲染产物**。流程：
1. `dd_extract_docx`/自写脚本提取全部批注+修订（含w:ins/w:del/pPrChange/rPrChange、作者、锚定段）
2. 逐条批注分类：格式类/内容类/需业务提供/待办保留

4. 重建/手术→QC key_checks逐条回查批注
5. 中断恢复=重跑渲染（content.json一步重建）

**终审人常见批注模式**（见实战沉淀）：格式未统一/表头居中/备注样式/行距/三级标题/可比公司重找/现金流改口径/补充某PDF结论/序号字体归属/前十大占比勾稽。

## 0b. 七个返工根因（动手前逐条自检，详见版本记录 v6.2）

①数据源层级不清 → 关键科目回**原始凭证**，不平强制回溯上一层
②口径不前置锁定 → 先写**口径三问**（主体/期间/分母）
③手改不可见 → **`w:ins=0` ≠ 无改动**，先与上一版 **diff**
④批注当字面指令 → **意图三问**，歧义追问一句
⑤改动不全链传播 → 查**影子位置**（表下导语段/表上备注/意见区/另一张表派生量）
⑥格式靠人眼 → 新增内容**机械校验 + 渲染验收**
⑦没有交付门禁 → 跑 §0 自检

## A. 数据矛盾检查（自动）
- 基础算术：总资产≈流动+非流动/总负债≈流动+非流动/净资产≈资产-负债/资产负债率≈负债÷资产
- **分项求和=合计（逐项，非≈）**：非流动资产=固定+在建+无形、流动资产明细=货币+应收+其他、负债明细之和=负债合计、营收-成本-费用+其他=净利。任一差（尤整数差如10万）多为**单科目转录错**——用"合计"做锚点反推分项锁定（客户丁：无形990.22→980.22）
  - **⚡v5.8起已自动化**：`dd_report_consistency.py` [1b] 门禁自动做块求和 + 利润表结构复算，差额>容差直接 FAIL 并**反查漏项**（单项 |v|≈|diff| 或双项 a±b≈diff）。**差额即线索**——客户庚0911：774.55=562.22+212.34、147.88=176.67−28.79，一比即知漏了谁
  - **但自动检覆盖不了"底稿串列"**：自动提取的上年列/期末列串位（客户庚：衍生金融资产188.90万实为2024年末、委托加工物资102.60万同）需人工回**扫描件原件**用"合计"行锚点复算
- 逻辑一致性：正文数字=表格数字/前文=后文/季度≠半年度/单体≠合并/"同比"≠"较年初"/"收入占比"≠"应收占比"/"设计产能"≠"有效产能"
- **比较级必落数值排序**："仅次于/第一梯队/领先/高于"用实际数值排一次序核对（417<445却称"仅次于工企、与沁园春相当"=实为第3）；禁用"相当/仅次于"模糊真实位次
- **关键事实单源**：同一事实（投产/验收/日期/产能/口径）全文多次出现统一为同一口径；一处定义其余引用。投产时点"8月/9月"前后矛盾必抓、统一
- **源数字对账（能力边界）**：报告引用的源数字必须对上原始凭证；**原始凭证是扫描件/图片≠无法核对**——用视觉直接读（fitz渲染→transpose转正→裁剪放大逐行读），勿因"无文字层"放弃。读扫描报表**只信无歧义的"合计/总计"行做锚点**，分项若"标签-数值列错位"读不实则标"存疑"，不猜不编
- **⚡⚡勾稽不平 = 强制回溯原始凭证（v5.9第一铁律，禁"记录差异"了事）**：任何勾稽差（现金流三活动≠现金净增减、分项和≠合计、表间数不平）**不是"待核实"备注就能过的**——必须立即索取/定位原始报表（哪怕扫描件），**逐栏比对定位到具体栏位**。差额本身就是线索：本案825.02万=误取"本期发生数"（6月单月）栏所致，更正后精确勾稽。**底稿是二手加工，关键科目必须回原始报表**；抄数前先确认栏位口径（"本期发生数"vs"本年累计数"、"期末数"vs"上年年末数"）
- **⚡实控人/董监高/股东 = 必须工商登记交叉核对，禁照抄业务报告（v5.9第二铁律）**：工商登记"主要人员"是最硬的一手证据。本案照抄业务报告写"总经理张甲"，工商登记实为张乙（总经理）/张丙（董事）/张丁（财务负责人），**张甲无任何任职登记**。配套：①**专有名词验真**（公司名/人名/项目名进正文前必查存在，"乡京锂业"查无此主体挂了三四轮）；②**公开报道的"露面反差"是实控人核查富矿**（谁受访、谁从不露面）；③人员穿透优先用有"人员关联/任职图谱"能力的接口（企查查 `get_executive_*`），关键词模糊搜索人名＝同名噪声地狱
- **⚡风险提示按10类标准检查表逐项过，没有的写"未见异常"**：①投产与履约 ②产品价格与品位 ③原材料供应与合同落地 ④关联方/同业竞争/技术依赖 ⑤实际控制人认定与关键人员披露 ⑥资质许可与合规 ⑦资金缺口与股东支持 ⑧财务信息质量与转固 ⑨担保增信落地 ⑩下游接受度/特殊合规（涉疆等）
