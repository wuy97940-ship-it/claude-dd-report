# 尽调报告批注驱动修改 · 固定套路（Playbook）

> v1.0 · 2026-09-13 · 从客户丁新材料走访前定稿 V11 轮次提炼
> 适用：拿到一份**已有终审人/审阅人批注与手改**的尽调报告 docx，要出下一版修订模式稿
> 配套：`skills/dd-report/SKILL.md`、`tools/docx_edit_lib.py`、`tools/dd_word_finalize.py`、`tools/dd_report_consistency.py`

---

## 〇、一句话总纲

**批注是需求文档，不是字面指令；数字要自己调研印证，改一处要扫全篇，改了参数要重算全链。**

## 〇·补、尽调报告的生命周期（v6.2 新增）

```
初稿 → 多轮修订 → 【走访前定稿】 → 现场走访 → 走访后修订 → 终稿
                     ↑ 必须在这里定一版
```

**走访前版本只回答"资料能回答的问题"**。只有实地才能回答的（实际采购价与单耗、工程形象进度/联动试车记录、代持书面确认、原料长协落地），**显式留成钩子**写进报告与访谈提纲，**不要靠推测填满**；同时在报告里留出"走访后要复测的模型口径"（如按"加工利润×产量"重建测算）。

**走访后**从 `…-走访后版本V1.docx` 起重启"修订模式 + 批注闭环"。

**提交前必跑自检门禁**：
```bash
python tools\dd_report_selfcheck.py <报告.docx> \
  --rename "旧术语=新术语|旧2=新2" --stale "废弃值1|废弃值2"
```
8 类检查（圈码hint/批注锚点/标点/表结构/口径统一/废弃值/重复段/修订统计），**FAIL>0 不得交付**；分隔符用 `|`。另配合 `dd_report_consistency.py`——**它看不到 `w:ins`，修订稿须先另存"接受修订后的临时副本"**。

## 〇·补2、七个返工根因（动手前逐条自检）

从客户丁全弧复盘提炼，**按代价排序**：

| # | 根因 | 代价实例 | 对策 |
|---|---|---|---|
| 1 | **数据源层级不清**（把业务报告/底稿提取当原始凭证） | 表7 取错栏位致 825.02 万不勾稽，**跨一个月四五轮没查出** | 层级 `原始凭证>审计报告>企业报表>业务报告>底稿提取`；下层不得作关键科目依据；不平**强制回溯**，禁"记录差异"了事 |
| 2 | **口径不前置锁定** | "15万/吨"三义（采购价/结算价/市场基准价）；盐湖净利率 47.26% vs 55.55% 差 8.29pct | 动手前写**口径三问**（主体/期间/分母） |
| 3 | **手改不可见** | 终审人先"接受全部修订"再手改，`w:ins=0` 但内容已变 | **`w:ins=0` ≠ 无改动**；每轮先与上一版 **diff** |
| 4 | **批注当字面指令** | "①序号和我的习惯不够"实为**字体**问题；"没有账期"是**推翻行业认知**；"不具可比性"是**换参照系** | **意图三问**；歧义**追问一句** |
| 5 | **改动不全链传播** | 改了参数没改**表下导语段**/表上备注/意见区/**另一张表派生量** | 维护"影子位置"清单，改完 grep 全部出现处 |
| 6 | **格式靠人眼** | 新增行列丢 `rPr`、圈码丢 `hint`、克隆表继承来源行加粗 | **机械校验 + 渲染验收** |
| 7 | **没有交付门禁** | 每轮靠零散手工检查 | 跑自检门禁 |

## 〇·补3、定稿后小修 = 直接改（不修订模式）

终审人指令："**不用修订模式，直接改**"。流程：
1. **先备份**原件（`_定稿_改前备份_<日期>.docx`）
2. 段落内**跨 run 物理替换**（保留原有 `rPr`，不留 `w:ins`/`w:del`）
3. **逐行比对全文**，确认**只有指定的那几处变化**
4. `dd_word_finalize.py --verify-only` 确认 Word 打开无修复提示、批注/修订计数不变
5. 通知改动清单

批量修改**先列清单请终审人勾选**，他勾哪条改哪条，**不替他决定保留与否**。

## 二、Step ① 定版本：先把"底稿"钉死

**动作**
1. 扫项目目录，按 mtime 排出版本线，与终审人确认底稿文件名（本轮：`…走访前版本.docx` 11:54）
2. **立即复制一份到独立工作区**（`_qaMMDD\_base_*.docx`），后续所有手术基于副本

**⚡铁律：无修订标记 ≠ 无改动**
终审人常**先"接受全部修订"再手改**，所以底稿里 `w:ins=0, w:del=0` **不代表他没动过**。
识别手改的唯一办法 = **与上一版做结构化文本 diff**。

- 本轮 diff（对「V10_独立复核版 alicia repo.docx」）抓出 4 处手改：
  1. 删「授信风险总体可控，」（他不要这类打包结论）
  2. 账期说明改「生产周期 30 天 / 买货周期 60 天」
  3. 表9 口径列「原料铝灰」→「原料铝渣（铝灰、辅料）」
  4. 「现金成本」→「现金生产成本」（他只改了正文，表格里还有 3 处——留给我举一反三）

**手改处绝对不碰**。与之有连带关系的修改（哪怕数字变了导致原话不再贴切）**必须先问**。

## 三、Step ② 提批注：三重定位，缺一不可

对每条批注要拿到 **① id/作者/时间 ② 完整文本 ③ 精确锚点块 + 前后文**。

**三个必踩的坑**

| 坑 | 症状 | 解法 |
|---|---|---|
| `id(lxml元素)` 不稳定 | 元素→块的映射表大面积取不到 | 用**祖先链**（`elem.getparent()` 逐级回溯）建映射，不用 `id()` |
| 遍历漏 `w:sdt` | 段落序号整体偏移（本轮偏 69，目录段全丢） | 遍历必须递归进 `sdt → sdtContent`；与全文导出的计数口径**必须一致** |
| 只取锚定区间文本 | 表格内批注只拿到几个字，判断不了意图 | 取**所在块完整文本**（段落全文 or 单元格全文）+ 前后各 3~4 块上下文 |

**按作者分类处置**
- **终审人（杨 吴）**：指令式，直接执行，但要看懂他真正要的是什么
- **其他审阅人（如 Alicia，业务口）**：多是**行业认知纠偏**，往往推翻一个前提而不只是改一句话

## 四、Step ③ 还原意图：三问 + 两类特殊批注

**三问**（沿用某贸易客户戊经验）：他在纠正什么？预期数据从哪来？我上一版哪个假设错了？

**⚡两类必须警惕的批注**

**A. 推翻行业认知的批注 → 改的是逻辑不是措辞**
- 例：Alicia「没有账期，或赊销账期较短」（锚在"碳酸锂销售存在一定账期"）
- 字面做法：删掉"账期"两字 ❌
- 正确做法：重写资金占用逻辑 →「资金占用主要体现为**主材采购的前置付款、生产过程中的资金沉淀、盘面套保的保证金追补**」✅

**B. 建议更换参照系的批注 → 改的是配置不是删表**
- 例：Alicia「客户庚/某参照上市公司不具有可比性，建议删除」+「如果要说明行业景气度，建议选取行业典型企业，比如行业头部锂企等」
- 字面做法：删掉整节和表 ❌
- 正确做法：**保留表格结构、更换主体与定性**——把"工艺可比公司"改为"行业景气度参照"（行业头部锂企），备注改写为"不构成本项目的工艺可比公司，仅反映行业整体景气水平" ✅

**C. 要求写入数字的批注 → 先调研再落笔**
- 例：终审人「这个单价区间可以写一下，我了解下来是 2000-7500 元」
- **绝对不要直接落笔**（用户原话：*"你要好好市场调研一下，而不是我写多少是多少，要和我了解的印证"*）
- 正确做法：先做市场调研 → 拿**同行可比公司实际中标价**印证 → 与他的口径对照成表 → 再写入正文 + 附来源日期 ✅

## 五、Step ④ 举一反三：一条批注 = 全文同类扫描

任何"事实口径变更"必须全文扫同类，**包括表格内**。

本轮实例："0.46 万元收入的性质"从"试生产/试运行"改为"建设期销售建筑废料"
```
扫描命中 6 处：
  P0099 意见区【基本面】(3)      → 改写
  P0105 风险1 投产与履约         → 改写
  P0230 利润表分析              → 改写
  P0245 财务综合评价            → 改写
  P0247 在建工程转固段 ⚡关键    → 论证链被推翻，重写
  表7-R1 说明列「试生产阶段样品/副产品收入」→ 改「建设期间销售建筑废料所得」
  表3-R8 状态列「在建/试生产」   → 改「在建」
```

**⚡特别提醒：转固段的论证会被推翻**
原报告用「已实现试生产销售收入 0.46 万元」论证"可能已具备生产能力却未转固"。一旦这笔收入不是试生产收入，**整个论证的前提就没了**，必须反向重写为"尚未形成试生产销售收入 + 项目未完工 → 未转固与资产状态基本相符"，同时保留"仍须以工程形象进度/联动试车记录核验"的钩子。

**同理**：增信安排变更（股权质押取消）→ 全文 2 处提及一并删改，且"三重增信"→"双重增信"。

## 六、Step ⑤ 修订写入：参数变了就重算全链

### 6.1 全链重算清单（本轮 14 处联动）

```
原料采购单价 2,752 元/吨
   └→ 单耗 30 吨/吨
        └→ 原料成本 82,560 元/吨
             └→ 现金生产成本 88,560 元/吨（替代原 35,000）
                  ├→ 表9 核心假设参数（新增 4 行）
                  ├→ 表10 基准情景 三档（收入/成本/毛利/利润总额/经营现金）
                  ├→ 表10 盈亏临界值（现金口径 39→74、含折旧 145→276）
                  ├→ 表10 临界现金成本倍数（4.1 倍 → 1.61~1.63 倍）
                  ├→ 表11 双因素矩阵 8 个格（含转负）
                  ├→ ★保本基准价（一句话结论：4.05万 → 9.41万元/吨）
                  ├→ 表12 铺底营运资金（1,458.33 → 3,690.00）
                  ├→ 表12 静态资金缺口（2,288.60 → 4,520.27）
                  ├→ 表13 动态月度（年末余额 3,097.23 → 865.56；压力情景转负）
                  ├→ 表13 备注②覆盖倍数（5.7~9.5倍 → 2.9~4.9倍）
                  ├→ 意见区【总体评估】(2) 全段
                  ├→ 第六章 (四) 测算结论 2 段
                  └→ 风险提示 7 资金缺口
```

**⚡必须产出"一句话结论"**
表格数字审批人不会逐格看，但 **"一期满产的利润总额盈亏平衡点对应碳酸锂基准价约 9.41 万元/吨"** 这种一句话，他会记住。参数变更后**第一件事就是算出新的保本点**，并与他熟悉的参照（2025年6月低点 5.99 万、2026 年中枢 15 万）并置。

**⚡重算极易漏的"影子位置"**（本轮全部踩过）
- 表**下面的**导语段（"基准情景按……35,000元/吨测算"——表改了导语没改）
- 表**上面的**备注段（覆盖倍数）
- 意见区里引用同一数字的那一段
- 结论章的收口段
- **另一张表**里的派生量（铺底营运资金 → 静态缺口）

### 6.2 修订模式的三个技术要点

| 场景 | 用什么 | 说明 |
|---|---|---|
| 改用户原文 | `tracked_replace(p, old, new)` | 出 `w:del` + `w:ins` |
| **改自己上轮的插入** | `ins_replace(p, old, new)` | 直接改 `w:t`，不叠加标记 |
| 整段是自建插入 | `set_ins_para(p, text)` | 同上 |

**⚡最常见的静默失败**：`tracked_replace` 只扫描**段落的直接子 run**。若目标文本在 `w:ins` 内部（=你自己上轮插进去的），它会**静默返回 False**——日志里必须打印每条成功/失败，不能只看最后有没有报错。

**表内插行**：多项插入**必须从下往上**（否则第二次克隆到刚插入的行 → 内容叠加）。
**插入新表**：
- 克隆文档现有表（格式母版），整表给每行加 `w:trPr/w:ins`
- **必须删掉克隆来的批注锚点三件套**（`commentRangeStart`/`End`/`Reference`），否则批注被复制成两份
- **必须逐列对齐 rPr 原型**——克隆到哪一行就继承哪一行的格式（本轮克隆源含一条加粗行，导致新表第 7 行莫名加粗被渲染出来）
- **⚡插入新表后，body 内表格索引整体后移**：若脚本后面还要"按索引改表 10/11/12"，全部会错位（本轮表 10~13 全 FAIL，排查一轮）。**按内容特征定位表格**，或插入后重算索引。

## 七、Step ⑥ 三层验收

| 层 | 手段 | 通过标准 |
|---|---|---|
| **文本层** | 自写扫描脚本 | 旧值残留 0；口径统一（如"现金成本"未加"生产"=0）；批注锚点 start=end=ref=12 |
| **结构层** | `dd_word_finalize.py --verify-only` | Word 打开无修复提示；页数/表数/批注数/修订数符合预期 |
| **视觉层** | **页范围**导出 PDF → 转 PNG 目检 | 新增表格格式与全表一致、跨页表头重复、无加粗/字号突变、无孤行断表 |

**⚡PDF 导出要用页范围**：含修订文档全量导出可能空转数分钟；`ExportAsFixedFormat(..., Range=3, From, To, ...)` 页范围导出 3~6 秒。
**⚡参数顺序**：`(OutputFileName, ExportFormat=17, OpenAfterExport, OptimizeFor=0, Range=3, From, To, Item=0, ...)`——Range 在前、From/To 紧随，写错会 `com_error -2147024809`。

**⚡一致性核对器要跑"接受修订后的临时副本"**
`dd_report_consistency.py` 基于 python-docx，**看不到 `w:ins` 内的文本**。直接跑修订稿 = 核对的还是旧值。正确姿势：
```
复制 V11 → _tmp_accepted.docx
dd_word_finalize.py _tmp_accepted.docx --accept --no-toc
dd_report_consistency.py _tmp_accepted.docx
对照底稿跑一遍，FAIL 数不增加 = 零新增问题
```
（本轮：底稿 FAIL=16、接受修订版 FAIL=16 → 完全一致，证明改动未引入新缺陷）

**⚡核对器的已知假阳性**（不必改报告，先核口径）
- **占比类**：核对器用"负债总额"作基数，报告备注声明的是"占资产总计"
- **变化率类**：核对器用全年同比，报告用的是"2025年全年÷12×6"同期折算口径（备注已声明）

## 九·补、第二轮新增（20260913 清洁稿→V12）

### 9.1 带圈序号"显示偏大" = 字体归属问题（终审人一眼看得出）
终审人批注：*"这个序号① ② ③，和我的习惯不够，尽调技能里面没有么？"* → 追问后：*"你看报告其他地方的序号，**你的序号大一点**"*。
- **不是**"该不该用①②③"的问题，**是**①②③ 的字体归属问题
- ①②③ 属 U+2460 区，**字体归属歧义字符**：run 的 `rFonts` 必须带 `w:hint="eastAsia"`，否则被 Times New Roman 接管、同字号下视觉偏大
- **为什么会丢**：`tracked_replace` 把整段塌缩成**一个克隆自"首个原型 run"的新 run**；原型不含圈码 → 无 hint → 新写的 ①②③ 全中招
- **铁律**：**每次手术收尾，全文扫描含圈码的 run 强制补 `rFonts/@w:hint="eastAsia"`**（校验脚本 `probe_circle.py`）
- 注意：正文圈码**本应**比备注圈码大（正文小四 vs 备注五号）；要比的是**同为正文的其他圈码**

### 9.2 "业务量超出授信额度"的落笔方式
> 终审人：*"额度我知道会超，但是业务部门目前只能选择2000万元，你可以括弧备注，按照《授信委托方信用管理办法》的有关要求…"*

## 十二、第三轮沉淀（20260914 上海某贸易客户戊 v14）——两轮制 / 结构级改动 / 口径与字体体检

### 12.1 把一轮拆成两轮跑
- **第一轮＝批注驱动的内容与结构改造**（删句、取中值、补量化证据、整节搬章、补股权留白、拆章＋章号重排）
- **第二轮＝口径与格式统修**（周转天数平均余额口径、字体三件套、表格 autofit、格式体检）
- 好处：结构改动不与口径/格式改动混在一起，**每轮各自可验收**（第一轮验收结构＋引用，第二轮验收数字＋字体）。
- 每轮收尾都跑：`dd_report_selfcheck.py`（FAIL=0）＋ **与底稿接受修订版逐行 diff 的 `dd_report_consistency.py`**（新增 FAIL=0）。

### 12.2 结构级改动（搬章/拆章）六要点
1. **搬章＝源处"整元素标删"＋新处"深拷贝标插"**，不要物理搬移（否则修订视图看不见变动、终审人无法审）。
2. **深拷贝优于按数据重建**：6 张表的格式/列宽/合并全量保留，零重建风险。
3. **批注锚点三件套**（`commentRangeStart/End/Reference`）**挪到"插入副本"**、源处剥离，避免同一批注出现两份。
4. 新章标题整段处于 `w:ins` 时，**Word 的 `TablesOfContents.Update()` 仍会收录它**（与旧经验"不显示"不同）。
5. `w:ins/w:del` 插进 `trPr`/`rPr` 时，必须排在 `trPrChange`/`rPrChange` **之前**（schema 顺序）。
6. **表定位串必须取唯一差异字段**：本轮两张"类别/指标"比率表表头几乎相同（仅第三列表头"2025年12月31日/2025年度" vs "2025年末/2025年度"不同），按含混串定位两次都命中第一张 ⇒ 母公司表没改、第一张表反被改错一格。**改完必须回读整张表验收。**

### 12.3 跨 `w:ins` 替换（最隐蔽的静默失败）
段落整段被"逐 run 包进 `w:ins`"时：`p.findall(w:r)`＝0 ⇒ `_delete_in_p` 静默返回空；而只在一个 `w:ins` 内正则搜也不够（一句话会被切成几十个 ins，本轮实测一段 40 个）。
**正解**：把该段**所有 `w:ins` 下的 `w:t` 按文档顺序拼成一个串**，正则定位后按 span 回写各节点（首节点留前缀+新值、末节点留后缀、中间置空）。判别法：段落直接 run＝0 且有 `w:ins` ⇒ 必须走这条路径。

### 12.4 周转天数口径体检（终审人20260914指令）
- 公式：应收＝平均应收÷营业收入×期间天数；存货/应付＝平均余额÷对应成本×期间天数；**年度365天、半年度180天**。

  **取数正确性交叉验证**：用报告里已有的"存货较上年末变动""毛利率"等派生值反算，能对上再落笔（本轮 7 家全部对上）。

### 12.5 字体体检三件套（"数字都是 TNR"）
**根因常在主题字体**：`word/theme/theme1.xml` 的 major/minor `latin` 若是"等线"，所有**未显式设 rFonts 的 run**（典型＝Word 生成的**目录页码**、部分表头）都会渲染成等线。
修法：①主题 latin → Times New Roman；②TOC1/TOC2… 样式显式指定西文 TNR（保证刷新目录后仍生效）；③含数字/西文却无 rFonts 的 run 逐条补 `rFonts ascii/hAnsi`。
判据：**"含 `[0-9A-Za-z]` 但 rFonts 非 TNR 的 run"＝0**。改 theme1.xml/styles.xml 属 zip 级改写（必要场景），**改完立即 Word 打开验证**。

### 12.6 注册资本/实缴资本对账范式
- 三源：**工商登记**（认缴＋变更记录）／**工商年报**（**实缴额＋实缴出资日期**，企查查 `get_annual_reports`，按年度更新、常滞后）／**公司报表**（实收资本，人民币、按各次出资记账汇率累计）。

- 落笔：写清"时点滞后 ＋ 外币/人民币记账口径"，并**单独标出尚未实缴的认缴额**（列授信前置/贷后跟踪）。

### 12.7 意见区必列担保主体（终审人20260914指令）
【基本面】**分列** "授信主体财务信息／担保主体财务信息（母公司，合并口径…）"两条，各按固定模板写足"最新期末＋上期＋两期变化"；担保主体条目**落到担保能力判断**（自身是否造血、靠股权融资还是集团内调度）；【重点风险提示】涉增信的条目同步引用其现金流与权益数据。
